# Security baseline and CVE response

Deployment checklist, default security behavior, and post-disclosure response contract (target ≤ 7 days to announce).
Self-review and external-audit scope: repository `docs/ga/security-audit.md`. External reporting channel: repository root `SECURITY.md`.

## 1. Default security baseline (secure out of the box)

| Item | Default behavior | Verify with |
| --- | --- | --- |
| admin channel | unix socket `/run/fasts3/admin.sock` (0600) or TCP loopback only + Bearer token | `fasts3d serve --admin-listen` config check |
| Replication port | when enabled, default 9445, **mTLS required**, certificate CN = `node_id`; does not use S3 :9000 | `[replication]` section / `fasts3d replication status` |
| S3 credentials | generated by `fasts3d init`, hashed into the store, **printed once only** | init output; admin keys page |
| TLS | init wizard self-signed bootstrap (CN+SAN, private key 0600); ACME and cert hot-reload supported | `deploy/tls/` |
| Anonymous access | off by default (`allow_anonymous=false`) | config check |
| Sensitive files | meta-export JSON lands 0600; TLS private key 0600 | `ls -l` (drill assertion) |
| Bucket names | IPv4-shaped bucket names rejected (anti-confusion) | CreateBucket 409 |
| Dependencies | cargo audit / pnpm audit 0-vuln gate (CI) | CI pipeline |

## 2. Deployment checklist (every item before go-live)

1. `fasts3d doctor` all green (device alignment / kernel features / IRQ / config correctness);
2. Data device is an **already-HA and consistent** block device; before init, no filesystem signature and no data
   (R7 red line: wizard hard-validates + second confirmation);
3. admin channel configured for least exposure (local unix socket preferred); token file permissions correct
   (0600), not in config templates;
4. TLS certificate chain valid (self-signed → replace with a real cert / ACME promptly); cert and private key permissions 0600;
5. systemd hardening unit parameters not weakened (`LimitMEMLOCK=infinity` /
   `NoNewPrivileges` / `ProtectSystem=strict`);
6. Backup system ready: meta-export snapshot + underlying volume snapshot dual insurance (run the drill script on a cycle);
7. Monitoring / alerts wired: Prometheus metrics + Grafana dashboard + alerts.yml
   (5xx / latency / clock jump / trusted-clock divergence / ring saturation);
8. Version and supply chain: use release artifacts with **signature + SBOM**; `Cargo.lock` /
   `pnpm-lock.yaml` committed; upgrades retain N-1 rollback. SBOM project-component license
   declared Apache-2.0 (same contract as root `LICENSE`).
9. **NTP/chrony always on** (hard gate for Object Lock deployments): wall clock must not jump backward during a run.
   FastS3 guarantees monotonicity during a run (a jump backward does not lift retention); **setting the clock across downtime** uses persisted
   `last_wall` as a lower bound only and cannot prove the wall clock was not jumped forward outside the downtime window — see ADR-13 promise boundary.
10. If primary/standby replication is enabled: replication port intranet-only, mTLS certs and CA in place; primary and standby share the same KMS;
    promote discipline: [Primary/standby replication](replication.md).

## 3. CVE response process (SLA ≤ 7 days)

| Stage | Action | Deadline |
| --- | --- | --- |
| Discover | External report (security contact) / internal audit / dependency advisory (cargo audit, pnpm audit, GitHub advisory) | Immediate |
| Assess | Reproduce → severity (Critical/High/Medium/Low) → blast radius (data plane / management plane / supply chain) | ≤ 24h |
| Fix | Branch fix + regression (full regression.sh) + ADR record (if there is a design trade-off) | ≤ 5 days |
| Announce | Ship a patch version + advisory (repository Security Advisories preferred; docs site in sync); include affected versions, mitigations, upgrade guidance | ≤ 7 days |
| Close | Add a vuln test case to the regression suite (prevent recurrence); review audit logs; if there is an external auditor, sync their review | Within 1 week of the fix |

**Contact**: prefer the code host's private vulnerability report; do not post exploit details on a public Issue.
Repository root `SECURITY.md` and [Community · security disclosure](../community/security.md).
External security-audit plan: `docs/ga/checklist.md`.

## 4. Identity integration (ADR-28 DI6; LDAP directory sync + bind login + OIDC console SSO)

> Management-plane feature; zero data-plane change (the data plane still only accepts access keys / SA). Config lives in
> web/server config.json (`ldap` / `oidc` sections) or `FS3_LDAP_*` /
> `FS3_OIDC_*` environment variables. From M18 R2, sync products are **IAM User/Group**,
> no longer "group → mint `k:` keys directly" (application keys are self-service service accounts created by users).

### 4.1 LDAP directory sync (users/groups → IAM User/Group)

```json
{
  "ldap": {
    "enabled": true,
    "url": "ldaps://ldap.corp:636",
    "bind_dn": "cn=fasts3-sync,ou=service,dc=corp",
    "base_dn": "ou=groups,dc=corp",
    "group_filter": "(objectClass=groupOfNames)",
    "groups": ["s3-admin", "s3-backup"],
    "user_filter": "(objectClass=inetOrgPerson)",
    "user_base_dn": "ou=users,dc=corp",
    "tenant": "default",
    "group_policies": { "s3-admin": ["readwrite"], "s3-backup": ["readonly"] },
    "sync_interval_secs": 300
  }
}
```

- **Bind password is allowed only via environment variable `FS3_LDAP_BIND_PASSWORD`**: if the config file contains a
  `bind_password` field it is ignored at load with a warning, and on-disk serialization strips the field.
- Directory user → IAM User (`tenant` configurable, default `default`): new users get
  `display_name = "ldap:<dn>"` (managed marker); disappearing from the directory → **disable, do not delete**;
  reappearing → re-enable. Same-named local users without the `ldap:` marker (including bootstrap)
  **are not taken over**; a `user.conflict` event is recorded.
- Directory group → IAM Group: members = directory members ∩ existing users in the tenant; policies =
  `group_policies` config (**whole-table takeover**). Group disappearing from the directory → clear members;
  the group and attached policies are kept; group removed from the `groups` config → IAM group is left alone (prevent accidental delete).
- **Bind password is held in process memory only**; not written to disk, not sent to the data plane, not audited
  (isomorphic with G1-3; ADR-21 DL1.3 held).
- Directory unreachable / bind failure → skip this round (touch no IAM entities, prevent accidental disable); status:
  `GET /api/ldap/status`; events: `GET /api/identity-events`.
- Residual `ldap-*` `k:` keys (minted by pre-R2 sync) are leftover bootstrap-owned keys; **not automatically
  deleted**; admins audit then revoke manually.
- `key_prefix` config field is deprecated (kept only for old config files; no longer takes effect).

### 4.2 LDAP bind login to the console (ADR-28 DI6.2)

- `POST /api/login` order: **local password users first**; on miss and LDAP enabled →
  BIND to the directory as `cn=<username>,<user_base_dn>` (password held in memory for that moment only).
- Bind success → look up same-named IAM User (ldap.tenant): **no matching User → 401 reject**
  (sync first, then log in; prevent ghost accounts); User disabled → 403; exists and enabled → issue
  the existing session JWT (8h), `sub` = username.
- Pre-C1 transitional contract: JWT `role` is derived from IAM attachments (attached `consoleAdmin` /
  `tenantAdmin` → `admin`, otherwise `readonly`); bind failure / directory unreachable →
  fallback result = 401 after local fallback (no silent allow).

### 4.3 OIDC console SSO (sub → IAM User, JIT into default group)

```json
{
  "oidc": {
    "enabled": true,
    "issuer": "https://sso.corp/realms/main",
    "client_id": "fasts3-console",
    "redirect_uri": "https://fasts3.example.com/",
    "role_claim": "roles",
    "admin_values": ["fasts3-admin"],
    "readonly_values": ["fasts3-viewer"],
    "fallback_role": "",
    "default_tenant": "default",
    "default_group": "sso-users"
  }
}
```

- Login page shows "Sign in with OIDC SSO": redirect to issuer authorize (implicit
  flow, `response_type=id_token`) → browser bounce-back carries id_token → server
  verifies (iss/aud/exp/nonce + JWKS RS256 or HS256 client_secret).
- **From M18 R2, `sub` maps to IAM User**: exists and enabled → role derived from IAM attachments
  (same transitional contract as above); disabled → 403; unknown sub → **JIT provision** into
  `default_group` (**that group must already exist**, otherwise 403 `oidc_jit_no_default_group`;
  `default_group` unset → 403 `oidc_jit_disabled`, no account created). JIT users get
  `display_name = "oidc:<sub>"`, **never attach policies directly, never get consoleAdmin** —
  permissions come entirely from the default-group attachment.
- role_claim mapping is used only to decide "login allowed": **hitting admin_values no longer elevates to
  admin** (capped at readonly); `fallback_role: "admin"` is likewise capped; no hit and
  `fallback_role` empty → login denied.
- Issuer unreachable → explicit error, fall back to local-account login; session lifetime does not depend on
  the issuer being online (stateless HS256).
- Trade-off: no authorization code + PKCE (implicit is enough for an intranet management plane;
  outside ADR-21 DL4 scope); STS `AssumeRoleWithLDAPIdentity/WebIdentity`
  (ADR-28 DI5.3) is not wired in this release; see the compat "IAM multi-tenant" section.

### 4.4 Identity audit

- `GET /api/identity-events?limit=N`: LDAP user/group reconciliation (user.created /
  user.disabled / user.enabled / user.conflict / group.created /
  group.updated / group.emptied / sync.skipped), bind login, and OIDC
  login/JIT events (in-memory ring buffer ≤500 entries, lost on process restart, documented; for
  persistence, hook log collection).

## 5. Encryption and customer keys

- **SSE-C**: customer keys appear only in request headers; console HEAD forwards `x-fasts3-sse-c-key`,
  **not in query / audit plaintext**; presigned SignedHeaders must accompany download / preview requests.
- **SSE-S3**: `GET /v1/admin/sse/status` / `POST .../rotate` expose only generation and progress,
  zero key material.
- **SSE-KMS** (v2.6): KEK never leaves the Vault/OpenBao process; plaintext DEK is not cached; stop KMS
  → `KMS.UnavailableException`. Primary and standby in a replication topology must share the same KMS.

## 6. Release-artifact trust chain

- **Signature**: minisign preferred, openssl pkeyutl ed25519 fallback (`tools/package/sign.sh`);
  public key published with RELEASES; verify: `tools/package/verify-release.sh`.
- **SBOM**: CycloneDX 1.5 (all Rust Cargo.lock components + web workspace packages;
  `tools/sbom/sbom.sh`); `metadata.component.licenses` declares the project contract
  Apache-2.0; archived with release artifacts.
- **Locking**: Cargo.lock / pnpm-lock.yaml committed; CI frozen install
  (`--frozen-lockfile`); dual zero-vuln dependency gates.
