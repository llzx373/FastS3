## 1. 总体目标与产品定义

### 1.1 成功标准:"开箱即用"的完整定义

FastS3 的终点不是一个能跑通的代码库,而是一个**陌生用户在一台空白机器上,5 分钟内装好、配好、用起来**的产品。据此定义产品完成度清单:

**① 安装体验(≤ 5 分钟)**
- [ ] 一条命令安装:`curl -fsSL ... | sh` / `apt install fasts3` / `dnf install fasts3` / `docker run`
- [ ] `fasts3 init` 交互向导:自动探测 NVMe/块设备 → 确认设备 → 初始化布局 → 生成管理员账号与首对 S3 密钥 → 引导生成/配置 TLS 证书(自签或 ACME)→ 启动服务
- [ ] 首次启动 30 秒内服务可用,Web 控制台可登录
- [ ] 升级一条命令(`fasts3 upgrade`),磁盘布局自动迁移,失败自动回滚
- [ ] 在 Debian/Ubuntu LTS、Rocky/Alma、ARM64 边缘设备上通过安装矩阵测试

**② 使用体验**
- [ ] aws cli / boto3 / mc / rclone 零配置对接(兼容矩阵全绿,见 DESIGN §12)
- [ ] Web 控制台覆盖完整运维闭环:仪表盘、桶、对象(直传)、密钥、策略、审计、设置
- [ ] 文档全覆盖:快速上手、管理员指南、性能调优、故障排查、FAQ、admin API 参考
- [ ] 内置示例与一键脚本(如"备份这个目录到 FastS3")

**③ 运维体验**
- [ ] systemd 单元与容器镜像双形态;健康检查 `/health`、`/ready`
- [ ] Prometheus 指标 + Grafana 仪表盘 JSON + 告警规则文件,一键导入
- [ ] `fasts3 doctor` 一键体检(设备对齐、内核特性、IRQ、配置正确性、性能基线对比)
- [ ] 备份/恢复:元数据快照工具 + 底层卷快照指南 + 恢复演练文档
- [ ] 迁移工具与指南:MinIO → FastS3(mc mirror)、公有云 S3 → FastS3(rclone)
- [ ] 日志可读可查:结构化日志 + 审计流水 + 常见错误码速查

**④ 安全与可信**
- [ ] 默认安全基线:admin 通道仅回环、随机 token、TLS 引导、secret 哈希存储
- [ ] 发布产物带签名与 SBOM(软件物料清单);CVE 响应流程(发现 → 修复 → 通告 ≤ 7 天)
- [ ] 外部安全审计(GA 前一次,之后每大版本一次)

**⑤ 性能承诺**
- [ ] 达到 DESIGN §6.8 目标表(相对 fio 裸盘基线),基准报告随版本发布
- [ ] 性能回归进入 CI 门禁,每版本出具基准对比

> 以上清单 = 产品验收标准。任何一项未勾选,不发布 1.0 GA。

## 2. 规划前提与资源假设

### 2.1 团队模型(基线:2 名全职 + 0.5 QA)

| 角色 | 代号 | 职责范围 |
| --- | --- | --- |
| 系统/存储工程师 | R | `fs3-device/alloc/engine/meta`、io_uring、崩溃恢复、性能调优、打包 |
| 全栈工程师 | W | `fs3-s3/http/admin` 中协议部分 + `fasts3-web` + 控制台 + 文档站 |
| QA(0.5 人,兼) | Q | s3-tests 适配、crash harness、兼容矩阵回归、发布验收 |

人力翻倍时可按 WBS 并行拆分(M0–M3 阶段并行度最高,见 §5)。

### 2.2 基础设施需求

- **CI**:常规 runner(编译/单测/lint)+ **1 台专用 NVMe runner**(Gen4 ×1 + Gen5 ×1),跑性能门禁与崩溃测试(崩溃测试需裸机或独占 VM);
- **测试设备矩阵**:裸 NVMe、镜像文件、慢盘(HDD,验证降级行为)、老内核机器(4.x,验证兜底路径);
- **Beta 环境**:公有云 2~3 台(不同云厂商的块存储)用于真实底座验证。

### 2.3 方法论

- **里程碑驱动 + 性能前置**:性能是核心卖点,不放在最后"优化",M0 就要有基准回路(见 §3.3),每个里程碑都测;
- **垂直切片**:每个里程碑交付"可演示的完整功能切片",不允许出现"所有模块都 80%"的横向豆腐渣;
- **设计先行、ADR 兜底**:设计文档的 ADR 是裁决依据,新决策必须新增 ADR 记录,避免走样。

## 3. 工程实践与质量门禁

### 3.1 分支与发布节奏

- `main` 永远可发布:所有变更 PR + 双人 review + CI 全绿;
- 发布轨道:
  - **nightly**:每夜构建,不承诺;
  - **beta**:每 2 周,功能冻结分支;
  - **stable**:每月 patch(安全/严重缺陷),每季度 minor(新功能),`CHANGELOG.md` 强制维护。

### 3.2 测试金字塔(门禁按里程碑收紧)

| 层 | 内容 | M1 | M4 | GA |
| --- | --- | --- | --- | --- |
| 单元测试 | 键编码、Range 裁剪、分配器、检查点、CRC、XML | ≥60% 覆盖 | ≥80% | ≥80% |
| 属性测试 | proptest:分配器随机序列、Range 代数、转义往返 | 核心模块 | 全模块 | 全模块 |
| 协议一致性 | CEPH s3-tests 子集 | 核心子集 | 全子集 | 全子集 100% |
| 客户端冒烟 | aws cli/boto3/mc/rclone 脚本矩阵 | 4 客户端 | 全矩阵 | 全矩阵每版本 |
| 崩溃一致性 | kill -9 混沌循环 | 100 轮 | 1000 轮 | 1000 轮 + 断电模拟 |
| 故障注入 | 磁盘满/掉盘/时钟回拨 | — | 全部场景 | 全部场景 |
| Fuzz | HTTP 解析、XML、SigV4 输入 | — | 基础 | 持续跑 |

### 3.3 性能回归门禁(与功能门禁同级)

1. M0 起建立:**fio 裸盘基线脚本 + 内部引擎基准**(设备层直测,不经过 S3 协议);
2. M2 起建立:**warp + 自研 loadgen 协议层基准**;
3. 每次合并到 `main` 跑快照基准,每里程碑跑全量基准;
4. 门禁规则:性能回退 > 5% 的 PR 禁止合并(需 ADR 豁免);每版本发布随附基准对比报告(含与 MinIO 对照)。

### 3.4 安全实践

- 依赖:CI 集成 `cargo audit` / `pnpm audit`,漏洞清零门禁;
- 密钥与机密:代码零硬编码,配置模板占位,CI secrets 管理;
- 发布:产物签名(minisign/ed25519)+ SBOM(cyclonedx)+ 供应链锁定(Cargo.lock 提交);
- 审查:GA 前一次外部审计;此后每大版本一次;修复窗口 SLA(见 §7.4)。

## 5. 里程碑计划

> 工期为日历周(2 人并行);每个里程碑有硬性退出条件,不达标不进入下一里程碑。

### M0 基础与引擎 PoC —— 2 周

- 任务:A1、B1、C1、D1、E1+E2(最小闭环)、A2
- 交付:裸设备/镜像文件 PUT/GET 全链路(无协议层)+ 基准回路
- 退出条件:**引擎级基准 ≥ fio 基线 70%**;kill -9 后重启可恢复位图;ADR 首轮验证通过

### M1 S3 核心语义 —— 3 周

- 任务:F1~F4、E3、G1、A3(初版)
- 交付:SigV4 + 桶/对象 CRUD + 列表 + Range,aws cli/boto3/mc/rclone 可跑通
- 退出条件:4 客户端冒烟通过;**s3-tests 核心子集 100%**;崩溃测试 ≥ 100 轮无撕裂

### M2 高级语义与零拷贝 —— 3 周

- 任务:F5~F7、B3、D2(零拷贝全量)、G2+G3、D5(可选提前)
- 交付:multipart、COW 复制、预签名、aws-chunked、h2、背压
- 退出条件:s3-tests multipart/copy 子集 100%;**协议层基准 ≥ 目标表 80%**;warp 混测无 OOM

### M3 管理面 v1 —— 3 周 ✅ 完成(v0.4,2026-08-21)

- 任务:H1+H2、I1~I3、J1~J3、E4、C4
- 交付:admin API + Node 管理 API + 控制台(仪表盘/桶/对象/密钥,含浏览器直传)
- 退出条件:控制台完成"建桶 → 拖拽上传 → 下载 → 删桶"全流程演示;`fasts3 check` 可用
- 验证:全流程演示通过;`fasts3 check` / `check --fix` 可用;v0.4 发布 + docs/perf-M3.md

> **近期(0~3 个月)结束点 = M0~M3,共 11 周 → 发布 v0.4「技术验证版」**:给内部/种子用户,验证性能假设与核心兼容性。

### M4 加固 —— 3 周 ✅ 完成(v0.5,2026-08-21)

- 任务:A3(千轮强化)、D4、H3、H4、I4、J4、审计与指标完备、TLS(rustls)
- 交付:崩溃恢复闭环、泄漏修复、配额限速、故障注入用例
- 退出条件:崩溃测试 1000 轮 + 断电模拟通过;磁盘满/掉盘/时钟回拨场景行为符合设计

### M5 性能冲刺 —— 3 周 ✅ 交付完成(v0.6,2026-08-21)

- 任务:G4(运行时 A/B)、MD5 多缓冲、IRQ 亲和/轮询模式、A4(loadgen 完整化)、L4(部分)

## 7. 版本与发布策略

### 7.1 版本规则(SemVer)

- `0.x`:预览,任何破坏不承诺;`1.0` 起:主版本破坏性变更、次版本新功能(向后兼容)、修订版修复;
- 磁盘布局版本独立编号(`layout_version`):布局变更必须携带自动迁移(init 时记录,upgrade 时执行),**迁移失败自动回滚**;
- admin API 与 Node 管理 API 均带 `/v1/` 前缀版本化;S3 协议本身无版本(以 AWS 行为为唯一标准)。

### 7.2 发布节奏

| 轨道 | 频率 | 内容 |
| --- | --- | --- |
| nightly | 每日 | 主分支自动构建,不承诺可用性 |
| patch | 每月 | 安全与严重缺陷修复(支持中的版本全线发布) |
| minor | 每季度 | 新功能(自 v1.1 起) |
| major | 按路线图 | v2.0 等 |

### 7.3 升级承诺

- 同机升级:优雅关闭(排空在途请求,≤ 5s)→ 布局迁移 → 启动自检 → 失败自动回滚上一版本;
- **永远支持 N-1 版本原地升级**(v1.2 可从 v1.1 直接升);跨多个 minor 提供逐级脚本;
- 布局迁移在低峰执行,数据面只读冻结窗口 < 30s(大位图重建为后台异步)。

### 7.4 支持与安全窗口

- 每个 minor 支持 12 个月;v1 LTS 支持 24 个月(安全修复);
- CVE 响应:SLO = 确认后 48h 内出评估、7 天内出修复 release;安全通告邮件列表 + 官网公告。
